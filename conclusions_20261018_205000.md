# TYK2 depth scan complete; batch variance limits 8-seed comparisons (20261018_205000)

Supersedes [conclusions_20261016_193000.md](conclusions_20261016_193000.md).

## Headline

**TYK2 P982A has no effect on the FERM–JH1 arrangement at any MSA depth.** The TYK2 positive control
(V678F) failed to validate the assay at the depth where it was first run, and is being re-run at the one
depth with a reproducible baseline. Separately, **batch-to-batch variance between 8-seed runs of the same
condition is as large as the mutation effects being measured**, which forces a re-reading of several
comparisons in this campaign.

## TYK2 MSA-depth scan (selected FERM–JH1 state per seed)

| depth | wild type | P982A | P982A vs WT |
|---|---|---|---|
| 32/64 | 15/15 compact | 15/15 compact | FERM–JH1 p = 0.10; JH2–JH1 p = 0.097 |
| 64/256 | 7/16 compact, 8/16 extended | 3/16 compact, 13/16 extended | Mann-Whitney p = 0.27 |
| 128/512 | 8/8 extended (~93 Å) | 8/8 extended (~93 Å) | 0.5 Å shift inside one state (p = 0.013) |

Wild type switches compact → mixed → extended as the MSA deepens; P982A follows the same switch. It leans
extended only in the mixed regime, and not significantly. TYK2's switch sits one step shallower than JAK3's
(JAK3 flips between 128/512 and 256/1024).

`TYK2_20261018_101316` (64/256), `TYK2_20261016_175018` (128/512). P982A: `TYK2_P982A_20261018_135623` +

## The positive control did not validate the assay

[TYK2_V678F_20261018_165935](TYK2/runs/TYK2_V678F_20261018_165935/conclusions.md) — V678F (the TYK2
equivalent of JAK2 V617F / JAK1 V658F) at 64/256, 8 seeds: **8/8 extended**, median 92.6 Å.

Against pooled wild type that looks like a hit (Fisher on extended counts p = 0.022). It is not:

| | extended | median | V678F vs this batch |
|---|--:|--:|---|
| WT seeds 0–7 | 1/8 | 56.3 | Fisher p = 0.0014 |
| WT seeds 8–15 | 7/8 | 92.1 | **Fisher p = 1.00** |
| V678F seeds 0–7 | 8/8 | 92.6 | – |

V678F is **indistinguishable from wild type's own second batch**. Its entire signal comes from wild type's
two halves disagreeing (1/8 vs 7/8 extended, p = 0.041). At 64/256 this assay cannot separate any mutation
from wild type.

V678F is now running at 32/64 (seeds 0–7 and 8–15), the only depth with a reproducible baseline — wild type
is 15/15 compact there across two independent batches. That decides whether the assay can detect activation
in TYK2 at all, and therefore whether P982A's null means anything.

## Batch variance: a campaign-wide caveat

Two 8-seed halves of the *same* condition, run hours or days apart on different sandboxes:

| condition | metric | first half | second half | half vs half |
|---|---|---|---|---|
| TYK2 WT 64/256 | FERM–JH1 | 1/8 extended | 7/8 extended | Fisher p = 0.041 |
| JAK3 M511I 128/512 | FERM–JH1 | 1/8 below 50 Å | 6/8 below 50 Å | MW p = 0.083 |
| JAK3 M511I 128/512 | distance to reference | median 88.8 Å | median 8.3 Å | **MW p = 0.036** |
| JAK3 A572V 128/512 | — | — | — | flagged in [mutation_analysis.md](mutation_analysis.md) |

Consequences:
- **Quote pooled 16-seed arms, never a single 8-seed half.** Each case above would have produced a confident
  wrong answer from one half alone.
- **A comparison is interpretable only where the wild-type baseline is reproducible across batches.** So far
  that is TYK2 at 32/64 (15/15 compact, halves agree) and 128/512 (8/8 extended), and JAK3 at 128/512
  (halves agree, p = 0.64). TYK2 at 64/256 is not.
- The P982A lean at 64/256 (13/16 vs 8/16 extended, p = 0.27) rests on that unstable baseline and should not
  be read as a direction.

This does **not** affect results where both arms agree across batches: TYK2 32/64 (all 30 seeds compact),
TYK2 128/512 (all 16 extended), and JAK3 M511I on FERM–JH1 (both arms 7/16 below 50 Å).

## JAK3 mutations at 128/512 — M511I completed

Two metrics are reported per mutation: the FERM–JH1 centroid distance, and distance to the mapped closed
reference (the classification used in [mutation_analysis.md](mutation_analysis.md); wild-type median 61.5 Å
reproduces exactly here). They do not always agree, which is itself informative.

| | FERM–JH1 median | vs WT | reference-distance median | vs WT |
|---|--:|---|--:|---|
| wild type (16) | 50.5 | – | 61.5 | – |
| **M592F** (16) | 55.0 | **p = 0.011**, more extended | 64.0 | p = 0.29 |
| **A573V** (16) | 42.0 | **p = 0.0020**, more compact | 2.7 | **p = 0.0024**, closer to closed |
| **A572V** (16) | — | **p = 0.035** (8-seed value was 54.5, p = 0.069) | 91.0 (8 seeds) | **p = 0.00094**, closed state abolished |
| **M511I** (16) | 52.9 | **p = 0.44, no effect** | 84.8 | **p = 0.82, no effect** |

[JAK3_M511I_20261018_173145](JAK3/runs/JAK3_M511I_20261018_173145/conclusions.md) added seeds 8–15, bringing
M511I to 16 seeds like the other mutants. **M511I has no effect on either metric.**

One caveat worth recording: 5 of 16 M511I seeds land within 15 Å of the reference against 0 of 16 for wild
type (Fisher p = 0.043), which in isolation would read as a hit. All five come from seeds 8–15, and M511I's
two halves differ from each other at p = 0.036 on that metric. The rank test over all 16 seeds shows nothing
(p = 0.82), so this is batch variance rather than an effect. Note A573V remains the wrong allele; A572V is
the reported one.

## Infrastructure

- **molab sandbox lifetime today: ~6.5 h** (two created ~10:40 were terminated ~17:05, mid-run). Plan at most
  two runs per sandbox, or start a fresh one after ~5 h.
- **Incremental backup runs alongside every job**: a local monitor copies each result file through the marimo
  file API every 3 minutes. When both 32/64 sandboxes died mid-run it preserved 7 of 8 seeds per arm, and the
  run folders were rebuilt from the backup (their `run_config.json` marks them as rebuilt; they lack the
  pipeline's `selection_report.json` and selected open/closed structures).
- **Results are pushed from the local machine**, not from molab: the notebook's push cell needs `GITHUB_TOKEN`
  inside the kernel, which is never set on a fresh sandbox.
- **Three failure modes, all now guarded:**
  1. *Stale FASTA.* Re-using a sandbox for a different protein leaves the old `<TARGET>.fasta` in the shared
     `fasta/` folder; the runner then tries to predict both targets and dies with `FileNotFoundError` on the
     missing alignment directory. Clear `fasta/` when switching target. This killed the first M511I attempt.
  2. *Disconnect interrupts the kernel.* marimo's `/api/kernel/execute` calls `session.try_interrupt()` when
     the HTTP client disconnects, so a timed-out status probe raises KeyboardInterrupt in the running cell.
     This cost three interrupts on 2026-10-17 and, on 2026-10-18, killed a kernel outright — the OpenFold
     subprocess was orphaned (reparented to init) and kept computing with no notebook to collect it. Monitor
     busy notebooks through `/api/status` and `/api/files/*` only.
  3. *Windows path length.* Backup paths exceed 260 characters; use the `\\?\` prefix or files fail silently.
